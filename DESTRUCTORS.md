# Деструкторы и RAII в L0

L0 поддерживает автоматическую очистку локальных экземпляров структур. Деструктор
— это метод структуры без параметров, имя которого **в точности совпадает с
именем структуры**. Его не нужно вызывать вручную: компилятор добавляет вызов
при выходе переменной из области видимости.

```l0
struct FileHandle {
    id: i32;

    function FileHandle()
        printf("closing {}", id)
    end
}

if 1 == 1 then
    let handle: FileHandle = FileHandle { id = 7 }
    print("using handle")
end
-- output: using handle
--         closing 7
```

## Когда вызывается деструктор

Автоматическая очистка применяется к переменным `let` типа структуры, созданным
в локальной области видимости. Она выполняется при:

- обычном завершении блока `if`, `while` и `for`;
- `break` и `continue`, включая выход из нескольких вложенных блоков;
- неявном завершении метода структуры;
- неявном завершении экспортируемой функции модуля;
- ошибке времени выполнения VM, например делении на ноль или выходе за
  границы массива/тензора.

Деструкторы вызываются в обратном порядке создания объектов (LIFO). Сначала
вызывается деструктор переменной из наиболее вложенного блока, затем — для
переменных внешних блоков.

## Условия и ограничения

- Имя деструктора — имя структуры: `function FileHandle() ... end` для
  `struct FileHandle`. Обычный метод, например `function close()`, не является
  деструктором и не вызывается автоматически.
- Если метода с именем структуры нет, структура остаётся допустимой, но не
  имеет автоматической очистки.
- Глобальные переменные не уничтожаются автоматически: их время жизни равно
  времени выполнения модуля/VM.
- В текущем синтаксисе L0 нет оператора `return`. Поэтому очистка на возврате
  относится к неявному `Return`, который компилятор добавляет в конец метода
  или экспортируемой функции.
- Ручной вызов деструктора не отменяет автоматический вызов при выходе из
  области видимости. Не вызывайте такой метод вручную, если операция очистки
  не является идемпотентной.

## Ошибки времени выполнения

После успешной инициализации локальной структуры VM регистрирует её как живой
объект. При ошибке VM прекращает обычное исполнение, проходит этот список в
обратном порядке и выполняет деструкторы. Исходная ошибка сохраняется и
возвращается вызывающему коду; ошибка, возникшая внутри деструктора при такой
аварийной очистке, не заменяет исходную ошибку.

Этот механизм является best-effort очисткой внутри L0 VM. Он не гарантирует
выполнение деструкторов при принудительном завершении процесса, аварии самого
Rust-процесса или при уничтожении VM внешним кодом без выполнения байткода.

## Регрессионные тесты

`scope_tst.l0` проверяет обычный выход из блоков, вложенные области,
`while`/`for`, `break`, `continue`, порядок LIFO, неявный выход из метода и
структуру без деструктора. В `lib.rs` добавлена отдельная Rust-проверка,
которая вызывает ошибку внутри метода и подтверждает обратный порядок
аварийной очистки.
